## [Unreleased]

### Ditambahkan
- **Fase 1 Selesai (Linux: Deteksi File Dasar & Integrasi YARA-X)**:
  - Integrasi engine YARA-X (pure Rust) dan penghitungan SHA-256 streaming di `gn-shield-rules`.
  - Database reputasi hash lokal (`HashReputationStore`) untuk hash malware yang sudah dikenal.
  - Deteksi signature standar EICAR antivirus test file terverifikasi.
  - Implementasi sensor filesystem inotify di Linux via `gn-shield-sensors-linux` (crate `notify`).
  - Implementasi pipeline evaluasi file bertingkat (`FileScanner`) di `gn-shield-core`: Layer 0 short-circuit Tier 1 Hash Allowlist, Tier 3 Path Allowlist, Hash Reputation, dan YARA-X scanning.
  - Parser konfigurasi TOML (`GnShieldConfig`) dengan dukungan allowlist di `gn-shield-config`.
- **Penetapan Nama Resmi: GN-Shield** (sebelumnya bernama Vigil). Struktur crate diperbarui menjadi prefix `gn-shield-*`.
- **Inisialisasi Repositori Git**: remote origin dikonfigurasi ke `git@github.com:hiroppi401/gn-shield.git`.
- **Script Build & Verifikasi Lokal**: penambahan `build.sh` untuk standarisasi format, linter clippy, dan testing tanpa ketergantungan CI eksternal.
- **Keputusan Arsitektur Final IPC**: Unix domain socket dengan format JSON-RPC (`serde_json`), secara sadar menolak gRPC demi efisiensi memory idle dan binary size.
- **Persyaratan Hak Akses IPC**: Mutasi state/allowlist wajib verifikasi hak akses administratif (UID=0 / polkit / sudo) untuk mencegah bypass dari proses lokal non-privileged.
- **Keputusan Migrasi Skema**: embedded migration via `PRAGMA user_version` SQLite di `gn-shield-storage`.
- **Pembaruan Scoring Decision Engine**: penambahan Ceiling/Veto Gate pada formula scoring di `docs/DECISION_ENGINE.md` untuk mencegah pengenceran (dilution) sinyal berbahaya tunggal yang ekstrem.
- Dokumen desain awal: README, PRD, AGENTS, THREAT_MODEL, ARCHITECTURE, DECISION_ENGINE, CONFIG_SCHEMA, ROADMAP, CONTRIBUTING.

- **Komponen baru: Browser Extension Companion** (`vigil-browser-extension` dan `vigil-native-host`), keputusan produk untuk menutup gap visibilitas di dalam browser (phishing konten, in-page cryptomining) yang tidak bisa dijangkau monitoring level OS. Ditambahkan ke `docs/ARCHITECTURE.md` bagian 3.9, `docs/THREAT_MODEL.md` bagian 2.6, `PRD.md` (tabel ancaman, non-goals, suite regresi), `docs/CONFIG_SCHEMA.md` bagian 9, dan `ROADMAP.md` Fase 4 baru (fase-fase berikutnya digeser). Nomor bagian di catatan ini mengikuti struktur final setelah beberapa kali renumbering, bukan nomor saat pertama ditulis. Komunikasi lewat native messaging, bukan TLS interception di level OS, supaya model keamanan HTTPS standar tetap utuh.
- Strategi publish/review dan method sync ditambahkan ke `docs/ARCHITECTURE.md` bagian 3.8.1 dan 3.8.2. Dikonfirmasi lewat riset bahwa developer mode/sideload bukan jalur distribusi viable (Chrome dan Firefox sama-sama mewajibkan jalur resmi store), dan teknik force-install lewat enterprise policy secara sengaja tidak dipakai karena menyerupai teknik silent-install adware/malware, melanggar prinsip consent eksplisit. Sync dengan `vigil-core` didesain lewat `sendNativeMessage` satu-arah (bukan koneksi persisten) karena service worker MV3 memang berhenti sendiri setelah idle, dan blocklist enforcement dilakukan lewat `declarativeNetRequest` supaya tidak membangunkan JS ekstensi tiap page load.
- Finalisasi strategi update Update Service (`docs/ARCHITECTURE.md` bagian 3.6, sebelumnya tercatat "belum diputuskan" di bagian 6): pull berkala dengan conditional HTTP request (ETag/If-None-Match), bukan WebSocket, supaya server bisa membalas 304 Not Modified saat tidak ada perubahan alih-alih mengirim payload penuh tiap siklus. Ditambahkan juga klarifikasi eksplisit di bagian 3.8.2 bahwa sinkronisasi ekstensi ke `vigil-core` adalah IPC lokal (bukan traffic jaringan), dan bahwa WebSocket di MV3 justru butuh keepalive tiap sekitar 20 detik (sejak Chrome 116) untuk menjaga service worker hidup, lebih boros dibanding desain `chrome.alarms` periodik yang sudah ada.
- Audit menyeluruh terhadap empat pillar (lightweight, secure, stable, reliable) menemukan dan memperbaiki lima celah tambahan: (1) syarat otorisasi untuk IPC lokal `vigil-core` ditambahkan ke `docs/ARCHITECTURE.md` bagian 6, supaya proses lokal lain tidak bisa menyuruh allowlist dirinya sendiri; (2) staleness warning digeneralisasi ke semua artifact Update Service (signature, hash reputation, default-allowlist), sebelumnya cuma PSL yang punya mekanisme ini; (3) NFR disk I/O idle ditambahkan ke `PRD.md` bagian 6.1; (4) kebijakan fail-open (bukan fail-closed) untuk browser extension kalau `vigil-core` tidak terhubung ditambahkan ke `docs/ARCHITECTURE.md` bagian 3.8.2, sebagai pengecualian sadar dari prinsip fail-closed yang berlaku di komponen lain; (5) asumsi enkripsi at-rest (mengandalkan LUKS/BitLocker/FileVault level OS, bukan Vigil sendiri) dan manfaat crash-safety WAL mode dicatat eksplisit di `docs/ARCHITECTURE.md` bagian 3.5. Ditambahkan juga item baru ke "Yang Belum Diputuskan": migrasi skema config/database antar versi rilis.
- **Komponen baru: IP Reputation Filter** (`docs/ARCHITECTURE.md` bagian 3.8, menggeser Browser Extension Companion dari 3.8 ke 3.9), menutup celah bypass DNS Filter (koneksi langsung ke IP hardcoded, atau DNS-over-HTTPS ke resolver luar yang melewati resolver lokal Vigil). Dibatasi sengaja sebagai deny-list terhadap IP dari feed reputasi curated (Feodo Tracker, Spamhaus DROP/EDROP), bukan firewall per-proses penuh, tanpa prompt user per koneksi (masuk kategori confidence tinggi auto-block yang sama dengan hash malware, `docs/DECISION_ENGINE.md` bagian 5). TTL entry lebih pendek dari domain blocklist (10 hari vs 45 hari) karena IP lebih sering di-recycle. Ditambahkan ke `PRD.md` (tabel ancaman, non-goals, suite regresi), `docs/CONFIG_SCHEMA.md` bagian baru, `docs/THREAT_MODEL.md` bagian 2.3, `ROADMAP.md` Fase 3, dan guardrail anti-scope-creep di `AGENTS.md`.
- Audit mendalam pada seluruh alur menemukan dan memperbaiki tujuh celah lagi: (1) **IPv6** ditambahkan sebagai syarat wajib (bukan opsional) di DNS Filter (dual-stack listen), IP Reputation Filter (data model dan enforcement hook AF_INET6), dan Sensor Network, karena kalau cuma IPv4 yang tercover itu jadi bypass baru persis yang coba ditutup fitur-fitur ini; (2) upstream DNS Filter wajib DoT/DoH, bukan DNS polos, supaya tidak rentan spoofing on-path; (3) TOCTOU pada on-access scan ditangani lewat fanotify permission mode (Linux) dan EndpointSecurity auth event (macOS), dengan Windows diakui punya residual risk karena keputusan menghindari minifilter driver; (4) proteksi rollback/replay ditambahkan ke Update Service (versi/timestamp monoton, bukan cuma signature); (5) path exclusion Tier 5 wajib resolve symlink dulu sebelum matching; (6) host manifest native messaging wajib dikunci permission sama ketat dengan config/database; (7) DNS Filter diberi mitigasi supaya tidak jadi single point of failure resolusi DNS sistem (restart cepat, anjuran resolver sekunder fallback).
- **Finalisasi mekanisme quarantine file** (sebelumnya tercatat "belum diputuskan" di `docs/ARCHITECTURE.md` bagian 6), ditambahkan sebagai `docs/DECISION_ENGINE.md` bagian 9 (Aksi Remediasi untuk Proses Berjalan): hentikan seluruh process tree, quarantine file (rename plus cabut bit executable, bukan delete langsung), tangani kasus self-delete evasion, putuskan koneksi jaringan aktif, notifikasi setelah tindakan bukan sebelum. Ditambahkan dua pengaman wajib: cek flag critical process sebelum terminate di Windows (mencegah bugcheck/BSOD), dan circuit breaker mass-kill (`docs/CONFIG_SCHEMA.md` bagian `[incident_response]`) supaya lonjakan auto-terminate akibat data hash reputation yang buruk tidak berubah jadi Vigil sendiri yang merusak sistem user.
- **Ditambahkan containment sebelum terminate** (`docs/DECISION_ENGINE.md` bagian 9, revisi urutan aksi remediasi): freeze proses (SIGSTOP/suspend, bukan kill langsung) lalu putus jaringan lalu blok filesystem lebih lanjut lalu observasi singkat untuk child process baru (scope ketat ke bawah, tidak pernah ke parent/sibling), baru terminate. Alasan: mencegah malware dengan dead man's switch/watchdog bereaksi agresif terhadap kill langsung. Ditambahkan kapabilitas gating dinamis per-PID di `docs/ARCHITECTURE.md` bagian 3.4.1 sebagai fondasi teknis.
- **Ditambahkan sinyal fan-out proses (mass child spawning)** ke `behavior_score` (`docs/DECISION_ENGINE.md` bagian 10) untuk deteksi pola worm/self-propagating, dipasangkan dengan allowlist flag `high_fanout_expected` untuk aplikasi multi-proses legitimate (browser, Docker/Podman/containerd, build tool paralel), meredam SATU sinyal spesifik saja tanpa meng-exempt child process dari pengecekan lain. Ditambahkan skenario suite regresi terkait di `PRD.md` bagian 6.4.
- Audit lanjutan menemukan dan memperbaiki tujuh temuan baru: (1) **malware fileless/living-off-the-land** (LOLBins, process injection) diakui sebagai blind spot signifikan di `docs/THREAT_MODEL.md` bagian 2.7, dimitigasi lewat scan YARA-X terhadap argumen command-line dan sinyal behavior_score baru untuk indikator process injection, ditambahkan ke `docs/DECISION_ENGINE.md` bagian 3; (2) flow uninstall eksplisit ditambahkan ke `PRD.md` bagian 7.5, wajib mengembalikan resolver DNS, host manifest, dan hook kernel ke kondisi semula supaya uninstall tidak membrick jaringan sistem; (3) syarat CO-RE (Compile Once Run Everywhere) untuk eBPF ditambahkan ke `docs/ARCHITECTURE.md` bagian 5, krusial untuk CachyOS yang rolling-release; (4) batas cakupan auto-rollback ransomware diperjelas di `docs/THREAT_MODEL.md` bagian 2.2, Vigil hanya mendeteksi dan memanfaatkan snapshot yang sudah ada, tidak mengelola jadwal snapshot sendiri; (5) keterbatasan rotasi signing key Update Service diakui eksplisit di `docs/ARCHITECTURE.md` bagian 3.6, tidak ada mekanisme rotasi otomatis di v1; (6) asumsi single-primary-user machine ditambahkan ke `PRD.md` bagian 9; (7) rootkit/kernel-level hiding ditambahkan sebagai non-goal eksplisit di `docs/THREAT_MODEL.md` bagian 1.

### Diubah
- Diperjelas batas cakupan exclusion Tier 5 di `docs/DECISION_ENGINE.md`. Exclusion `node_modules`/`.git`/`target` hanya berlaku untuk detektor ransomware, tidak untuk static malware scan atau process behavior monitoring. Perubahan ini dipicu oleh pertanyaan valid soal risiko package npm yang sudah disusupi (supply chain attack) bisa jadi tidak terdeteksi kalau exclusion ditafsirkan terlalu luas. Ditambahkan syarat arsitektural eksplisit: ketiga detektor (ransomware, static scan, behavior monitor) harus terpisah secara kode supaya exclusion satu detektor tidak ikut melemahkan detektor lain.
- Ditegaskan bahwa komputasi eTLD+1 di Tier 4 domain allowlist wajib memakai library Public Suffix List (crate `psl`/`addr`), bukan string suffix matching naif, karena status "private suffix di PSL" tidak sama dengan trust dan matching naif rentan bypass. Ditambahkan ke `docs/DECISION_ENGINE.md` Tier 4 dan `docs/ARCHITECTURE.md` bagian 3.6/5.
- Diubah desain PSL menjadi dua lapis (compiled-in `psl` sebagai fallback, `publicsuffix` sebagai lapis dinamis yang diperbarui Update Service di runtime) supaya freshness PSL tidak bergantung pada rebuild binary manual yang berisiko terlupa. Ditambahkan tracking staleness (`psl_stale_warning_days`) ke `docs/CONFIG_SCHEMA.md` dan status refresh ke `vigil-cli status`.
- Ditambahkan Tier 3b (Ephemeral Trust Cache) di `docs/DECISION_ENGINE.md` untuk mengatasi false positive berulang pada binary hasil build sendiri yang hash-nya selalu berubah. Cache time-boxed dengan sliding TTL (default 4 jam) berbasis direktori plus nama file, tidak pernah membatalkan static scan atau behavior monitoring, dan kedaluwarsa otomatis untuk membatasi jendela risiko. Konfigurasi terkait ditambahkan di `docs/CONFIG_SCHEMA.md` bagian 8 (setelah renumbering).
- Crosscheck menyeluruh menemukan dan memperbaiki beberapa celah: (1) strategi scanning bertingkat untuk YARA-X ditambahkan di `docs/ARCHITECTURE.md` 3.4.1 supaya ruleset besar tidak membebani CPU/memory/disk, termasuk verdict cache berbasis hash, prioritas OS-level rendah untuk scan worker, dan larangan full disk rescan otomatis saat signature update; (2) Update Service dipisah jadi subsection sendiri (3.6) dengan requirement verifikasi signature kriptografis sebelum update diterapkan, karena sebelumnya jalur ini belum punya spesifikasi integritas sama sekali; (3) penamaan "Tier 5" di `docs/DECISION_ENGINE.md` diperjelas bukan bagian dari stack override yang sama dengan Tier 1-4, dan dua jalur keputusan (scoring umum vs detektor ransomware berbasis kondisi eksplisit) dipisahkan secara eksplisit di bagian 1; (4) ancaman "attacker menyasar Vigil sendiri" (tamper resistance) ditambahkan ke `docs/THREAT_MODEL.md` bagian 5 dengan cakupan v1 yang jujur dan terbatas; (5) batching write dan WAL mode ditambahkan ke storage (`docs/ARCHITECTURE.md` 3.5) untuk menghindari disk I/O tersembunyi dari audit log; (6) `scan_queue_max_concurrent` diubah jadi adaptif terhadap jumlah core, bukan angka tetap; (7) NFR beban skala (load test) ditambahkan ke `PRD.md` bagian 6.1.
