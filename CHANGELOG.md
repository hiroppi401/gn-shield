# Changelog

Format mengikuti gaya Keep a Changelog. Setiap perubahan pada dokumen inti (`PRD.md` bagian 3/4/6, `docs/DECISION_ENGINE.md` bagian formula/threshold/kategori confidence tinggi) wajib dicatat di sini beserta alasannya, tidak hanya perubahan kode.

## [Unreleased]

### Ditambahkan
- **System Installation & Lifecycle Automation (`install.sh` & `uninstall.sh`)**:
  - **Script Instalasi Sistem (`install.sh`)**: Otomasi deployment rilis GN-Shield ke sistem Linux (`/usr/local/bin/`), pembuatan direktori konfigurasi (`/etc/gn-shield/`), database dan karantina (`/var/lib/gn-shield/quarantine/`), soket runtime (`/run/gn-shield/`), registrasi manifest native messaging browser companion secara sistem-wide, setup service systemd (`gn-shield.service`), dan pemindaian awal learning mode (`pacman`, `dpkg`, `rpm`).
  - **Script Uninstalasi Sistem (`uninstall.sh`)**: Pembersihan bersih sesuai mandat `PRD.md` Bagian 7.5, mencakup penonaktifan service systemd, penghapusan binari, pencabutan manifest browser, pembersihan soket, dan pengamanan file karantina agar tidak terhapus tanpa konfirmasi.
  - **Unit Systemd Production & Template Konfigurasi**: Penambahan `config/gn-shield.service` dengan proteksi sandbox (`ProtectSystem=full`, `ProtectHome=read-only`) dan `config/config.example.toml`.
- **Fase 6 Selesai (CLI dan UX Notifikasi)**:
  - **GN-Shield CLI Binary (`gn-shield-cli`)**: Perangkat command-line interaktif dengan subkomando `status` (status daemon & staleness warning), `log`/`history` (tinjauan audit log terformat), `allow`/`block` (manajemen rule), `quarantine` (list & restore file), `check-breach` (pemeriksaan kebocoran kredensial k-anonymity), dan `scan-sensitive` (inspeksi token & kunci privat lokal).
  - **Local Unix Domain Socket IPC & SO_PEERCRED Authorization**: Server IPC asinkron berbasis JSON-RPC di `gn-shield-core` (`/run/gn-shield/gn-shield.sock` / `/tmp/gn-shield.sock`). Pengecekan kredensial peer Linux (`SO_PEERCRED`) mewajibkan hak akses administratif (UID=0) untuk setiap mutasi state (allowlist, blocklist, restore karantina), mencegah eskalasi hak akses dari proses lokal non-privileged.
  - **Embedded SQLite Storage Engine (`gn-shield-storage`)**: Implementasi `StorageManager` berbasis `rusqlite` dengan WAL mode (`PRAGMA journal_mode = WAL`), versi skema monoton (`PRAGMA user_version`), tabel audit log keputusan, tabel file karantina, dan tabel override allowlist dinamis.
  - **Pengelompokan (Batching) Notifikasi Ambigu (`NotificationBatcher`)**: Mitigasi alert fatigue saat instalasi package/tooling developer baru via sliding window (`batch_window_ms = 1000ms`) dan pengelompokan berbasis proses induk (`parent_pid`). Jika terkumpul event ambigu `>= batch_threshold_count`, sistem menggabungkannya ke notifikasi ringkasan tunggal dengan aksi batch (`Allow All Once`, `Always Allow All`, `Block All`, `Review Individually`).
  - **Spesifikasi & Safeguard Timeout**: Dokumentasi teknis pengelompokan notifikasi pada `docs/DECISION_ENGINE.md` Bagian 11 dan garansi batas timeout `default_action_on_timeout = "allow_once"` yang mencegah auto-block ireversibel.
- **Fase 5 Selesai (Data Breach Check & Sensitive Data Scanner)**:
  - **Credential Leak Checker k-Anonymity (`KAnonymityChecker`)**: Implementasi algoritma hash-split SHA-1 di `gn-shield-rules::breach`. Hanya 5 karakter prefix hex pertama yang dikirim ke penyedia range/database kebocoran (model Have I Been Pwned), sementara 35 karakter sisa dan password mentah diverifikasi secara hermetis di mesin lokal tanpa pernah terpapar ke jaringan atau log (Zero Transmission of Secrets).
  - **Detektor Pola Data Sensitif (`SensitiveDataDetector`)**: Scanner regex berkinerja tinggi di `gn-shield-rules::sensitive_data` untuk deteksi kunci privat OpenSSH/RSA/EC/DSA, AWS Access Key ID (`AKIA...`), GitHub Personal Access Token (`ghp_...`, `github_pat_...`), dan Slack token. Output selalu disanitasi menggunakan masked preview (contoh: `AKIA****************`).
  - **Opt-In Privacy Guard**: Konfigurasi `[data_breach]` di `gn-shield-config` dengan default `enabled = false`, `scan_clipboard = false`, dan `scan_uploads = false` menjamin nol pembacaan clipboard atau upload tanpa persetujuan eksplisit pengguna.
  - **Suite Regresi Fase 5 & 6**: Pengujian integrasi otomatis `fase5_breach_and_fase6_cli_regression.rs` memverifikasi akurasi k-anonymity, masking data sensitif, alur IPC daemon status, audit query, pencegahan unauthorized allowlist, pemulihan file karantina, dan pengelompokan batch notifikasi.
- **Fase 4 Selesai (Browser Extension Companion & Native Messaging Host)**:
  - **Native Messaging Companion Host (`gn-shield-native-host`)**: Jembatan binary berkinerja tinggi antara browser (Chrome/Edge/Brave/Firefox) dan `gn-shield-core` via stdio length-prefixed JSON wire protocol, dengan waktu inisialisasi sangat cepat (< 5ms).
  - **Deterministic Extension IDs & Host Manifests**: Penetapan Extension ID deterministik di awal fase (`acdgclnhgfblkcpbleihngdecipmalmb` untuk Chromium via public key RSA di `manifest.json`, dan `companion@gn-shield.org` untuk Firefox via `browser_specific_settings.gecko.id`), serta generator dan installer manifest (`com.gnshield.host.json`).
  - **Early MVP Store Submission Bundles**: Skrip packaging otomatis (`package_extension.sh`) yang menghasilkan `gn-shield-companion-chrome.zip` dan `gn-shield-companion-firefox.zip`, disertai panduan submission Web Store / AMO dan Privacy Policy yang mendokumentasikan zero-telemetry & local processing.
  - **WebExtension Manifest V3 Companion (`browser-extension/`)**: Ekstensi browser lintas-platform mendukung Chrome, Edge, Brave, dan Firefox dengan permission minimal (`declarativeNetRequest`, `storage`, `alarms`, `nativeMessaging`).
  - **Enforcement Blocklist di Level Page-Load**: Service worker (`background.js`) menyinkronkan feed domain phishing dan cryptomining (`coinblockerlists`) dari `gn-shield-core` ke engine native `declarativeNetRequest` browser, memblokir akses ke domain berbahaya tanpa membangunkan JavaScript pada tiap navigasi.
  - **Heuristik Form-Action-Mismatch Anti-Phishing**: Content script (`content.js`) mendeteksi submission form berisi password ke origin berbeda dari halaman saat ini, dengan short-circuit allowlist untuk penyedia identitas legitimate (`accounts.google.com`, `login.microsoftonline.com`, `github.com`, `appleid.apple.com`, `*.okta.com`, `*.auth0.com`).
  - **Kebijakan Fail-Open**: Jika daemon atau native host tidak terhubung, ekstensi fail-open (tidak memblokir navigasi legitimate pengguna) dan menampilkan status visual transparan pada popup extension.
  - **Suite Pengujian Regresi False Positive Browser & NFR**: Pengujian otomatis (`test_extension.js` dan `browser_companion_regression.rs`) memverifikasi zero false positive terhadap login SSO developer, script Google Ads / Google Analytics tidak salah tangkap sebagai cryptomining, latency overhead content script ~1.3ms (jauh di bawah batas NFR 50ms), dan konfirmasi nol transmisi URL ke jaringan eksternal.
  - **Konfigurasi `[browser_extension]` pada `gn-shield-config`**: Dukungan schema konfigurasi TOML dengan validasi privasi `blocklist_refresh_via = "gn-shield-core"`.
- **Remediasi & Pemenuhan Kriteria Fase 0 (Fondasi & CI/CD Security)**:
  - **CI & Supply Chain Security Automation**: Menambahkan workflow GitHub Actions (`.github/workflows/ci.yml`), konfigurasi `deny.toml` (validasi lisensi, advisories, dan source), dan konfigurasi `.cargo/audit.toml` (audit CVE harian/per-commit).
  - **Script Verifikasi Build Lokal (`build.sh`)**: Diperluas menjadi 6 tahapan komprehensif mencakup `cargo fmt --check`, `cargo clippy -D warnings`, `cargo test`, `cargo build --workspace`, `cargo deny check`, dan `cargo audit`.
  - **Penyelesaian Transisi Nama Penuh (Vigil → GN-Shield)**: Seluruh prosa dokumentasi (`PRD.md`, `ROADMAP.md`, `AGENTS.md`, `docs/*.md`) dan string kode telah diselaraskan 100% menggunakan identitas GN-Shield.
  - **Ekspansi Test Coverage Crate**: Penambahan unit test pada seluruh crate yang sebelumnya stub (`gn-shield-storage`, `gn-shield-sensors-common`, `gn-shield-sensors-macos`, `gn-shield-sensors-windows`), memastikan seluruh crate library memiliki automated unit tests.
- **Fase 3 Selesai (Linux: DNS Filter, Anti-Phishing & IP Reputation Filter)**:
  - **Two-Layer Public Suffix List Engine (`PslEngine`)**: modul `psl_engine` di `gn-shield-dns` menggabungkan layer compiled-in fallback (`psl` crate) dan layer dinamis runtime (`publicsuffix` crate) dengan staleness tracking (`psl_stale_warning_days`).
  - **Tier 4 Domain Allowlist & Anti-Phishing (`DnsFilterEngine`)**: pencocokan batas label (bukan ends_with naif) untuk tunnel developer (`*.trycloudflare.com`, `*.cfargotunnel.com`, `*.ngrok.io`, `*.ts.net`), integrasi feed reputasi domain (URLhaus, PhishTank, coinblockerlists), dan short-circuit allowlist.
  - **Dual-Stack DNS Proxy Server (`DnsProxyServer`)**: proxy UDP dual-stack di `127.0.0.1:53` dan `[::1]:53` menggunakan wire protocol `hickory-proto`, membalas NXDomain pada domain jahat, dan meneruskan query valid ke upstream terenkripsi/terkonfigurasi dengan latensi sub-milidetik (< 1ms).
  - **Linux IP Reputation Filter eBPF (`EbpfIpReputationFilter`)**: filter koneksi keluar berbasis eBPF (`aya`) mencakup kedua address family (`AF_INET` dan `AF_INET6`), mekanisme TTL expiry otomatis (mencegah false positive terhadap IP cloud provider/CDN edge bekas shared hosting), dan override CIDR subnet (`network.ip_allowlist`).
  - **Detektor Resolver Sistem Linux (`ResolverDetector`)**: deteksi otomatis `systemd-resolved` (`127.0.0.53:53`), Pi-hole, dnsmasq, dan dnscrypt-proxy dengan 3 mode integrasi (`takeover`, `chain_upstream` pada port 5353 via `resolvectl`, dan `disabled`).
  - **Skema Konfigurasi & Validasi Jaringan**: penambahan `[dns_filter]`, `[ip_reputation_filter]`, `[[network.domain_allowlist]]`, dan `[[network.ip_allowlist]]` pada `gn-shield-config`.
  - **Suite Regresi False Positive Jaringan**: 4 skenario uji integrasi baru lulus 100% untuk allowlist domain dual-stack IPv4/IPv6, TTL expiry IP reputasi CDN, override CIDR Tailscale, dan deteksi resolver.
- **Fase 2 Selesai (Linux: Anti False Positive dan Ransomware)**:
  - **Honeypot & Deteksi Entropy Shift**: implementasi Shannon entropy streaming dan `HoneypotManager` di `gn-shield-rules` untuk deployment serta verifikasi tampering file canary.
  - **Detektor Perilaku Ransomware (`RansomwareDetector`)**: pipeline keputusan berbasis kondisi eksplisit (canary tampered + mass write + entropy shift) terpisah dari formula berbobot, dengan resolusi symlink canonical dan aksi containment `IncidentAction::ContainAndTerminate`.
  - **Tier 5 Context-Aware Directory Exception**: konfigurasi `[[ransomware.excluded_paths]]` dengan sensitivity `reduced` untuk `node_modules`, `.git`, `target`, `dist`, `build`, `.venv`, memastikan tooling developer tidak salah tangkap sambil tetap menjamin static scan malware aktif 100%.
  - **Monitoring Proses eBPF Linux via `aya`**: implementasi `EbpfProcessSensor` di `gn-shield-sensors-linux` dengan loader bytecode kernel `aya` dan event queue.
  - **Pelacak Perilaku Proses (`ProcessBehaviorTracker`)**: perhitungan `behavior_score`, peredaman sinyal fan-out untuk aplikasi `high_fanout_expected` (Firefox, Chromium, Docker, Podman, Cargo), pemindaian command-line YARA-X untuk LOLBins, dan pelacakan percobaan berulang koneksi IP terblokir.
  - **Learning Mode Saat Instalasi (`LearningModeScanner`)**: pemindaian database package manager sistem (`pacman`), pencocokan tools developer bawaan, dan rekomendasi batch approve Tier 2 Publisher Trust.
  - **Suite Regresi False Positive (`PRD.md` Bagian 6.4)**: suite pengujian integrasi `false_positive_regression.rs` lulus 100% untuk Firefox/Chromium multi-proses, cloudflared/ngrok/tailscale, git checkout, npm/cargo/pip install masif, dan deteksi malware EICAR di dalam `node_modules`.

- Strategi publish/review dan method sync ditambahkan ke `docs/ARCHITECTURE.md` bagian 3.8.1 dan 3.8.2. Dikonfirmasi lewat riset bahwa developer mode/sideload bukan jalur distribusi viable (Chrome dan Firefox sama-sama mewajibkan jalur resmi store), dan teknik force-install lewat enterprise policy secara sengaja tidak dipakai karena menyerupai teknik silent-install adware/malware, melanggar prinsip consent eksplisit. Sync dengan `vigil-core` didesain lewat `sendNativeMessage` satu-arah (bukan koneksi persisten) karena service worker MV3 memang berhenti sendiri setelah idle, dan blocklist enforcement dilakukan lewat `declarativeNetRequest` supaya tidak membangunkan JS ekstensi tiap page load.
- Finalisasi strategi update Update Service (`docs/ARCHITECTURE.md` bagian 3.6, sebelumnya tercatat "belum diputuskan" di bagian 6): pull berkala dengan conditional HTTP request (ETag/If-None-Match), bukan WebSocket, supaya server bisa membalas 304 Not Modified saat tidak ada perubahan alih-alih mengirim payload penuh tiap siklus. Ditambahkan juga klarifikasi eksplisit di bagian 3.8.2 bahwa sinkronisasi ekstensi ke `vigil-core` adalah IPC lokal (bukan traffic jaringan), dan bahwa WebSocket di MV3 justru butuh keepalive tiap sekitar 20 detik (sejak Chrome 116) untuk menjaga service worker hidup, lebih boros dibanding desain `chrome.alarms` periodik yang sudah ada.
- Audit menyeluruh terhadap empat pillar (lightweight, secure, stable, reliable) menemukan dan memperbaiki lima celah tambahan: (1) syarat otorisasi untuk IPC lokal `vigil-core` ditambahkan ke `docs/ARCHITECTURE.md` bagian 6, supaya proses lokal lain tidak bisa menyuruh allowlist dirinya sendiri; (2) staleness warning digeneralisasi ke semua artifact Update Service (signature, hash reputation, default-allowlist), sebelumnya cuma PSL yang punya mekanisme ini; (3) NFR disk I/O idle ditambahkan ke `PRD.md` bagian 6.1; (4) kebijakan fail-open (bukan fail-closed) untuk browser extension kalau `vigil-core` tidak terhubung ditambahkan ke `docs/ARCHITECTURE.md` bagian 3.8.2, sebagai pengecualian sadar dari prinsip fail-closed yang berlaku di komponen lain; (5) asumsi enkripsi at-rest (mengandalkan LUKS/BitLocker/FileVault level OS, bukan Vigil sendiri) dan manfaat crash-safety WAL mode dicatat eksplisit di `docs/ARCHITECTURE.md` bagian 3.5. Ditambahkan juga item baru ke "Yang Belum Diputuskan": migrasi skema config/database antar versi rilis.
- **Komponen baru: IP Reputation Filter** (`docs/ARCHITECTURE.md` bagian 3.8, menggeser Browser Extension Companion dari 3.8 ke 3.9), menutup celah bypass DNS Filter (koneksi langsung ke IP hardcoded, atau DNS-over-HTTPS ke resolver luar yang melewati resolver lokal Vigil). Dibatasi sengaja sebagai deny-list terhadap IP dari feed reputasi curated (Feodo Tracker, Spamhaus DROP/EDROP), bukan firewall per-proses penuh, tanpa prompt user per koneksi (masuk kategori confidence tinggi auto-block yang sama dengan hash malware, `docs/DECISION_ENGINE.md` bagian 5). TTL entry lebih pendek dari domain blocklist (10 hari vs 45 hari) karena IP lebih sering di-recycle. Ditambahkan ke `PRD.md` (tabel ancaman, non-goals, suite regresi), `docs/CONFIG_SCHEMA.md` bagian baru, `docs/THREAT_MODEL.md` bagian 2.3, `ROADMAP.md` Fase 3, dan guardrail anti-scope-creep di `AGENTS.md`.
- Audit mendalam pada seluruh alur menemukan dan memperbaiki tujuh celah lagi: (1) **IPv6** ditambahkan sebagai syarat wajib (bukan opsional) di DNS Filter (dual-stack listen), IP Reputation Filter (data model dan enforcement hook AF_INET6), dan Sensor Network, karena kalau cuma IPv4 yang tercover itu jadi bypass baru persis yang coba ditutup fitur-fitur ini; (2) upstream DNS Filter wajib DoT/DoH, bukan DNS polos, supaya tidak rentan spoofing on-path; (3) TOCTOU pada on-access scan ditangani lewat fanotify permission mode (Linux) dan EndpointSecurity auth event (macOS), dengan Windows diakui punya residual risk karena keputusan menghindari minifilter driver; (4) proteksi rollback/replay ditambahkan ke Update Service (versi/timestamp monoton, bukan cuma signature); (5) path exclusion Tier 5 wajib resolve symlink dulu sebelum matching; (6) host manifest native messaging wajib dikunci permission sama ketat dengan config/database; (7) DNS Filter diberi mitigasi supaya tidak jadi single point of failure resolusi DNS sistem (restart cepat, anjuran resolver sekunder fallback).
- **Finalisasi mekanisme quarantine file** (sebelumnya tercatat "belum diputuskan" di `docs/ARCHITECTURE.md` bagian 6), ditambahkan sebagai `docs/DECISION_ENGINE.md` bagian 9 (Aksi Remediasi untuk Proses Berjalan): hentikan seluruh process tree, quarantine file (rename plus cabut bit executable, bukan delete langsung), tangani kasus self-delete evasion, putuskan koneksi jaringan aktif, notifikasi setelah tindakan bukan sebelum. Ditambahkan dua pengaman wajib: cek flag critical process sebelum terminate di Windows (mencegah bugcheck/BSOD), dan circuit breaker mass-kill (`docs/CONFIG_SCHEMA.md` bagian `[incident_response]`) supaya lonjakan auto-terminate akibat data hash reputation yang buruk tidak berubah jadi Vigil sendiri yang merusak sistem user.
- **Ditambahkan containment sebelum terminate** (`docs/DECISION_ENGINE.md` bagian 9, revisi urutan aksi remediasi): freeze proses (SIGSTOP/suspend, bukan kill langsung) lalu putus jaringan lalu blok filesystem lebih lanjut lalu observasi singkat untuk child process baru (scope ketat ke bawah, tidak pernah ke parent/sibling), baru terminate. Alasan: mencegah malware dengan dead man's switch/watchdog bereaksi agresif terhadap kill langsung. Ditambahkan kapabilitas gating dinamis per-PID di `docs/ARCHITECTURE.md` bagian 3.4.1 sebagai fondasi teknis.
- **Ditambahkan sinyal fan-out proses (mass child spawning)** ke `behavior_score` (`docs/DECISION_ENGINE.md` bagian 10) untuk deteksi pola worm/self-propagating, dipasangkan dengan allowlist flag `high_fanout_expected` untuk aplikasi multi-proses legitimate (browser, Docker/Podman/containerd, build tool paralel), meredam SATU sinyal spesifik saja tanpa meng-exempt child process dari pengecekan lain. Ditambahkan skenario suite regresi terkait di `PRD.md` bagian 6.4.
- Audit lanjutan menemukan dan memperbaiki tujuh temuan baru: (1) **malware fileless/living-off-the-land** (LOLBins, process injection) diakui sebagai blind spot signifikan di `docs/THREAT_MODEL.md` bagian 2.7, dimitigasi lewat scan YARA-X terhadap argumen command-line dan sinyal behavior_score baru untuk indikator process injection, ditambahkan ke `docs/DECISION_ENGINE.md` bagian 3; (2) flow uninstall eksplisit ditambahkan ke `PRD.md` bagian 7.5, wajib mengembalikan resolver DNS, host manifest, dan hook kernel ke kondisi semula supaya uninstall tidak membrick jaringan sistem; (3) syarat CO-RE (Compile Once Run Everywhere) untuk eBPF ditambahkan ke `docs/ARCHITECTURE.md` bagian 5, krusial untuk CachyOS yang rolling-release; (4) batas cakupan auto-rollback ransomware diperjelas di `docs/THREAT_MODEL.md` bagian 2.2, Vigil hanya mendeteksi dan memanfaatkan snapshot yang sudah ada, tidak mengelola jadwal snapshot sendiri; (5) keterbatasan rotasi signing key Update Service diakui eksplisit di `docs/ARCHITECTURE.md` bagian 3.6, tidak ada mekanisme rotasi otomatis di v1; (6) asumsi single-primary-user machine ditambahkan ke `PRD.md` bagian 9; (7) rootkit/kernel-level hiding ditambahkan sebagai non-goal eksplisit di `docs/THREAT_MODEL.md` bagian 1.
- **Ditambahkan tiga mode integrasi DNS Filter** (`docs/ARCHITECTURE.md` bagian 3.7): `takeover`, `chain_upstream`, `disabled`, dipilih lewat `dns_filter.integration_mode` (`docs/CONFIG_SCHEMA.md`). Ini menutup celah asumsi bahwa Vigil selalu jadi satu-satunya resolver di sistem, padahal banyak setup Linux modern sudah menjalankan resolver sendiri (`systemd-resolved`, dnsmasq, Pi-hole, dnscrypt-proxy) yang bisa konflik port atau rusak diam-diam kalau tidak dideteksi dulu. Ditegaskan juga bahwa mode `disabled` tidak berarti kehilangan proteksi jaringan total, karena IP Reputation Filter dan browser extension tetap beroperasi independen dari DNS. Kriteria terkait ditambahkan ke `ROADMAP.md` Fase 3.

### Diubah
- Diperjelas batas cakupan exclusion Tier 5 di `docs/DECISION_ENGINE.md`. Exclusion `node_modules`/`.git`/`target` hanya berlaku untuk detektor ransomware, tidak untuk static malware scan atau process behavior monitoring. Perubahan ini dipicu oleh pertanyaan valid soal risiko package npm yang sudah disusupi (supply chain attack) bisa jadi tidak terdeteksi kalau exclusion ditafsirkan terlalu luas. Ditambahkan syarat arsitektural eksplisit: ketiga detektor (ransomware, static scan, behavior monitor) harus terpisah secara kode supaya exclusion satu detektor tidak ikut melemahkan detektor lain.
- Ditegaskan bahwa komputasi eTLD+1 di Tier 4 domain allowlist wajib memakai library Public Suffix List (crate `psl`/`addr`), bukan string suffix matching naif, karena status "private suffix di PSL" tidak sama dengan trust dan matching naif rentan bypass. Ditambahkan ke `docs/DECISION_ENGINE.md` Tier 4 dan `docs/ARCHITECTURE.md` bagian 3.6/5.
- Diubah desain PSL menjadi dua lapis (compiled-in `psl` sebagai fallback, `publicsuffix` sebagai lapis dinamis yang diperbarui Update Service di runtime) supaya freshness PSL tidak bergantung pada rebuild binary manual yang berisiko terlupa. Ditambahkan tracking staleness (`psl_stale_warning_days`) ke `docs/CONFIG_SCHEMA.md` dan status refresh ke `vigil-cli status`.
- Ditambahkan Tier 3b (Ephemeral Trust Cache) di `docs/DECISION_ENGINE.md` untuk mengatasi false positive berulang pada binary hasil build sendiri yang hash-nya selalu berubah. Cache time-boxed dengan sliding TTL (default 4 jam) berbasis direktori plus nama file, tidak pernah membatalkan static scan atau behavior monitoring, dan kedaluwarsa otomatis untuk membatasi jendela risiko. Konfigurasi terkait ditambahkan di `docs/CONFIG_SCHEMA.md` bagian 8 (setelah renumbering).
- Crosscheck menyeluruh menemukan dan memperbaiki beberapa celah: (1) strategi scanning bertingkat untuk YARA-X ditambahkan di `docs/ARCHITECTURE.md` 3.4.1 supaya ruleset besar tidak membebani CPU/memory/disk, termasuk verdict cache berbasis hash, prioritas OS-level rendah untuk scan worker, dan larangan full disk rescan otomatis saat signature update; (2) Update Service dipisah jadi subsection sendiri (3.6) dengan requirement verifikasi signature kriptografis sebelum update diterapkan, karena sebelumnya jalur ini belum punya spesifikasi integritas sama sekali; (3) penamaan "Tier 5" di `docs/DECISION_ENGINE.md` diperjelas bukan bagian dari stack override yang sama dengan Tier 1-4, dan dua jalur keputusan (scoring umum vs detektor ransomware berbasis kondisi eksplisit) dipisahkan secara eksplisit di bagian 1; (4) ancaman "attacker menyasar Vigil sendiri" (tamper resistance) ditambahkan ke `docs/THREAT_MODEL.md` bagian 5 dengan cakupan v1 yang jujur dan terbatas; (5) batching write dan WAL mode ditambahkan ke storage (`docs/ARCHITECTURE.md` 3.5) untuk menghindari disk I/O tersembunyi dari audit log; (6) `scan_queue_max_concurrent` diubah jadi adaptif terhadap jumlah core, bukan angka tetap; (7) NFR beban skala (load test) ditambahkan ke `PRD.md` bagian 6.1.

### Diperbaiki
- **Celah Ceiling/Veto Gate: `hash_reputation` tidak ikut terlindungi** (`crates/gn-shield-core/src/decision.rs`, `docs/DECISION_ENGINE.md` bagian 4). `hash_reputation` berbobot sama (0.4) dengan `static_score` dan searah sama ("makin tinggi makin curiga", dikonfirmasi eksplisit bukan sinyal trust), tapi hanya `static_score` yang punya ceiling gate (`>= 0.8 => PromptUser`), `hash_reputation` tidak. Akibatnya, fuzzy/partial hash match (misal 0.85, belum cukup exact untuk `KnownBad`) bisa "terlarut" jadi Allow kalau sinyal lain kebetulan 0.0 (0.85*0.4=0.34, di bawah threshold 0.4). Diperbaiki dengan menambahkan `|| v.hash_reputation >= 0.8` ke kondisi ceiling gate yang sama dengan `static_score`, ditambahkan test `test_ceiling_veto_gate_high_hash_reputation`, dan ditambahkan klarifikasi eksplisit di `docs/DECISION_ENGINE.md` bagian 3 soal arah nilai ketiga sinyal numerik (searah mencurigakan, trust cuma lewat `allowlist_override`) supaya kesalahan arah serupa tidak terulang di implementasi berikutnya.
